Concepts

Every card runs a real operation against MongoDB and shows the evidence on screen: the stored values, the measured sizes, the query plans, the rejections. Turn on Developer view to see the exact mongosh behind each one.

Computed Pattern

stored value vs recomputed value

The average rating and the counts are calculated once, when a loan is returned, and stored on the book. Pages then read them directly instead of aggregating every loan on every view. Below, MongoDB recomputes the same numbers from scratch so you can see they agree.

Extended Reference Pattern

snapshot inside the loan vs $lookup

Each loan keeps a copy of the book's title and authors next to the real reference (book.book_id). A loan history therefore needs one read, with no join. The price of the shortcut is that the copy can go stale if the book is edited later. That is a deliberate trade-off, because a loan should show the title as it was when the book was borrowed.

Outlier Pattern

sizes measured with $bsonSize

A few popular books collect far more reviews than the rest. Embedding every review inside the book would make those documents grow without limit, and MongoDB caps a document at 16 MB. Books past the threshold are flagged has_many_reviews and their reviews move to reviews_overflow. The sizes below are measured by the database itself.

BSON types, embedding and referencing

$type on every field

MongoDB itself reports the type of each stored field. The role column says whether the value is embedded in the document, a reference to another collection, a snapshot, or a computed value.

Index lab

planner choice vs forced full scan

The same query is run twice with explain("executionStats"): once as the query planner chooses, once forced to read the whole collection with hint({ $natural: 1 }). Compare how many documents each had to examine. Some presets deliberately have no index, so you can see what a missing index looks like.

Schema validation

$jsonSchema, error 121

Each button inserts a bad document straight into MongoDB, skipping every check the application normally does first. The database rejects it. The last button inserts a correct document to prove good data is accepted, and deletes it again. These inserts need a signed-in account.
